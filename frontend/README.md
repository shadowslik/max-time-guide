# Рядом — навигатор досуга по свободному времени

Фронтенд mini-app для решения на платформе **MAX** (чат-бот + mini-app) в рамках
трека «Досуг и развлечения». Это чистое mini-app без стенда и обвязки: то, что
открывается из чат-бота.

> Данные о местах — **тестовые, заранее подготовленные** (центр Казани).
> В боевой версии подставляется реальный источник (2ГИС / OpenStreetMap / афиши).

## Идея

Человек в командировке / проездом получает свободный час-другой в незнакомом городе.
Вместо «вот 20 достопримечательностей рядом» продукт спрашивает: **сколько у тебя времени** —
и показывает только те места, куда реально успеть сходить **и вернуться**, с учётом дороги
туда-обратно и запаса времени.

Формула проблемы: *турист/командированный в чужом городе со свободным окном 1–3 ч хочет
провести его с пользой, но тратит время на поиск и не знает, что успеет, — и в итоге не идёт никуда.*

## Основной пользовательский сценарий

1. **Чат-бот MAX** — приветствие, определение геопозиции (геолокация / точка на карте / адрес).
2. Кнопка «Найти, куда сходить» открывает **mini-app**.
3. **Подтверждение места** старта.
4. **Сколько времени** — ключевой экран с визуальным «бюджетом времени» (дорога · на месте · запас).
5. **Интересы** — быстрый выбор (можно пропустить).
6. **Подбор** — экран, показывающий, что продукт считает под капотом.
7. **Результаты** — интерактивная карта с метками; тап по метке → карточка с раскладом времени
   и статусом 🟢 Успеваешь / 🟡 Впритык / 🔴 Не успеешь.
8. **Маршрут** — таймлайн «выход → дорога → место → возвращение» и открытие в Яндекс.Картах.
9. **Цепочка** — если после одного места остаётся запас, собираем маршрут из двух.
10. **Ничего не успеть** — честный фоллбэк с ближайшим вариантом и кнопкой «+30 минут».
11. **Изменить** — быстрая правка времени и интересов поверх результатов.
12. **Мои маршруты** — история поездок с повтором (вход — иконка часов на первом экране).

## Стек

- **React 19** + **Vite 5**
- **@maxhub/max-ui** — провайдер `<MaxUI>` задаёт тему (light/dark) и платформу (iOS/Android)
  в стилистике MAX; сам интерфейс собран на собственных компонентах по дизайн-макетам.
- **JS API Яндекс.Карт 2.1** — настоящие карты, метки и ссылка «Открыть маршрут».
- Схематичная SVG-карта — фоллбэк, когда ключа к API нет или он не сработал.

## Яндекс.Карты

Ключ JS API кладётся в `.env.local` (шаблон — в `.env.example`):

```bash
VITE_YANDEX_MAPS_API_KEY=ваш-ключ
```

Используется **JS API 2.1**. Это важно: ключи выдаются под конкретную версию, и
ключ от 2.1 на эндпоинте 3.0 отвечает `403 Invalid api key`. Проверить версию
ключа можно так — рабочая версия вернёт ~35 КБ JS, неподходящая отдаст 403:

```bash
curl -s -o /dev/null -w "%{http_code}
" -H "Referer: http://localhost:5173/"   "https://api-maps.yandex.ru/2.1/?apikey=КЛЮЧ&lang=ru_RU"
```

В кабинете API у ключа должно быть задано **ограничение по HTTP Referer или IP** —
без него ключ не активируется. Для локальной разработки достаточно значения
`localhost` (порт поле не принимает).

Без ключа приложение **полностью работоспособно**: вместо тайлов рисуется схематичная
карта центра Казани из дизайн-макетов, метки и маршруты размещаются на ней.
Если ключ задан, но API не загрузился, происходит тот же откат — в консоль пишется
предупреждение с вероятной причиной, экран не ломается.

### Что входит в бесплатный тариф, а что нет

По официальной странице тарифов Яндекса:

| Продукт | Бесплатный тариф |
|---|---|
| JavaScript API | да, с суточным лимитом |
| Geocoder API | да, 1000 запросов в сутки |
| Routing API (маршруты, матрица расстояний) | **нет**, от 226 200 ₽ в год |

Поэтому линия маршрута рисуется прямой пунктирной, а не по улицам: роутер
платный. Тайминги это не затрагивает — их считает свой планировщик.

**Геокодер бесплатный**, но его нужно отдельно подключить к ключу в кабинете.
Сейчас он не подключён, поэтому координаты в `src/data/places.js` проставлены
вручную (погрешность — десятки метров).

Условия бесплатного использования: сервис должен быть открыт и бесплатен для
всех, применяться на некоммерческой основе, и **обязан показывать кнопку
«Открыть в Картах», копирайт и ссылку на условия**. Прятать их нельзя — поэтому
в CSS копирайт специально поднят над шторкой, а блок «Открыть в Картах» не
подавляется.

### Ограничение, важное при смене провайдера карт

Условия (пп. 6.1.1, 6.2.1, 6.6.1) запрещают **обратное направление**: выводить
результаты работы Геокодера, Маршрутизации и Панорам Яндекса в сервисах третьих
лиц или на чужих картографических материалах.

Практическое следствие: если когда-нибудь переедем с Яндекс.Карт на другой
провайдер (например MapLibre + OSM), нельзя будет взять с собой координаты и
маршруты, полученные через API Яндекса — их придётся получить заново из
открытых источников. Поэтому координаты в `places.js` сейчас проставлены
вручную, а не геокодером: так данные ни к чему не привязаны.

Тайминги подбора всегда считает собственный планировщик (`src/lib/planner.js`) —
он не зависит от сети и от тарифа, поэтому демо предсказуемо.

### Тёмная тема карты

У JS API 2.1 нет тёмной схемы. В тёмной теме мы инвертируем **только слой тайлов**
(`ground-pane`) CSS-фильтром — метки, плашки и копирайт остаются в своих цветах.

## Тема и платформа

Mini-app не рисует собственных переключателей: тема берётся из окружения MAX
(`src/lib/maxBridge.js`), а если приложение открыто вне мессенджера — из
`prefers-color-scheme`. Смена темы подхватывается на лету, все 13 экранов
нарисованы в обеих темах.

## Структура

```
src/
  App.jsx                   # состояние поездки и навигация между экранами
  data/places.js            # тестовые данные: места, интересы, история, опции времени
  lib/
    planner.js              # evaluatePlace / pickPlaces / buildChain — ядро подбора
    format.js               # время, длительности, склонения
    ymaps.js                # загрузка JS API Яндекс.Карт + фоллбэк
    maxBridge.js            # тема, платформа и внешние ссылки через MAX
  styles/
    tokens.css              # дизайн-токены светлой и тёмной темы
    app.css                 # каркас, кнопки, шторки, чипы
    screens.css             # экранные блоки
  components/
    MapCanvas.jsx           # карта: Яндекс или схема, метки, маршруты
    SchematicMap.jsx        # схема центра Казани из макета
    MapPin.jsx              # метки-капли
    TimeBudgetBar.jsx       # полоса бюджета времени — ключевая механика
    Timeline.jsx            # таймлайн маршрута
    KremlinArt.jsx          # иллюстрация в шапке карточки места
    Icon.jsx, ui.jsx        # иконки и примитивы интерфейса
  screens/                  # 13 экранов сценария
```

## Логика «успеваешь / не успеваешь»

Для каждого места `дорога туда + время на месте + дорога обратно + запас (10 мин)`
сравнивается с доступным временем (`src/lib/planner.js → evaluatePlace`):

- **Успеваешь** (зелёная метка) — хватает на комфортный визит;
- **Впритык** (жёлтая) — успеваешь при сокращённом визите;
- **Не успеешь** (серая) — не хватает даже на минимальный визит; место остаётся на карте с пометкой.

`buildChain` перебирает пары подходящих мест, считает переход между ними по координатам
и выбирает пару, где суммарно больше времени «на месте» при уложенном бюджете.

## Известные ограничения

- Данные о местах и времена пешком — статические демо-значения по центру Казани,
  не из реального гео-API. Координаты проставлены вручную.
- Маршрут на карте — прямая линия между точками: роутер Яндекса не входит в тариф ключа.
- Нет бэкенда: история поездок живёт в памяти вкладки.
- Фото мест заменены схематичной иллюстрацией — прав на реальные снимки нет.

Эти части — «переменная» часть решения; ядро (сценарий, логика подбора под время,
структура интерфейса) переносится в другой город без изменений.
