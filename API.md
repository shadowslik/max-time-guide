# API mini-app «Рядом» — гайд для бэкенда

Документ описывает контракт между mini-app и бэкендом: какие ручки нужны,
что они принимают и возвращают, и какой код во фронтенде их дёргает.

Сейчас фронтенд работает **без бэкенда**: подбор считается в браузере
(`frontend/src/lib/planner.js`), ключи внешних API лежат в клиентском бандле,
история поездок живёт в памяти вкладки. Этот документ — план, как это разделить.

## Зачем вообще бэкенд

Три причины, по убыванию важности.

1. **Общая логика с ботом.** Чат-бот должен уметь сказать «нашёл 3 места» до
   того, как человек откроет mini-app. Если подбор живёт во фронтенде, боту
   придётся написать вторую реализацию той же формулы — и они разъедутся.
2. **Ключи.** У Routing API и геокодеров нет защиты по referer. Ключ в
   клиентском бандле виден любому, кто откроет DevTools.
3. **Кэш.** Каталог мест конечный, поэтому переходы между местами — матрица,
   которая считается один раз и живёт вечно. Сейчас каждый браузер запрашивает
   их заново.

## Общие соглашения

| Тема | Решение |
|---|---|
| Базовый путь | `/api` |
| Формат | JSON, UTF-8 |
| Координаты | `[долгота, широта]` — порядок GeoJSON, MapLibre и ORS |
| Время | минуты, целые числа |
| Расстояние | метры, целые числа |
| Даты | ISO 8601 в UTC (`2026-09-26T13:40:00Z`) |
| Авторизация | заголовок `Authorization: tma <initData>` — подпись MAX |

### Формат ошибки

Один на все ручки:

```json
{ "error": { "code": "invalid_coordinates", "message": "Долгота вне диапазона" } }
```

| HTTP | Когда |
|---|---|
| `400` | не прошла валидация входных данных |
| `401` | нет или невалидна подпись MAX |
| `404` | место или поездка не найдены |
| `429` | исчерпан лимит внешнего API |
| `502` | внешний сервис (роутер, геокодер) не ответил |

Фронтенд обязан пережить **любую** ошибку: подбор не должен ломаться из-за
того, что роутер лёг. Ниже у каждой ручки описано, что показывать при сбое.

## 1. `POST /api/search` — подбор мест

Главная ручка. Заменяет `pickPlaces` и `buildChain` из `lib/planner.js`.
Её же дёргает чат-бот, чтобы ответить «нашёл N мест» без открытия mini-app.

### Запрос

```json
{
  "start": [49.1086, 55.7951],
  "minutes": 120,
  "interests": ["history", "arch"],
  "startAt": "2026-09-26T13:40:00Z"
}
```

| Поле | Тип | Обязательное | Смысл |
|---|---|---|---|
| `start` | `[number, number]` | да | точка, которую пользователь поставил на карте |
| `minutes` | `integer` | да | сколько у него свободного времени, 15–240 |
| `interests` | `string[]` | нет | пустой массив или отсутствие = «покажи что угодно» |
| `startAt` | ISO 8601 | нет | момент выхода; по умолчанию — сейчас |

### Ответ

```json
{
  "found": 5,
  "fits": 4,
  "places": [
    {
      "id": "kremlin",
      "name": "Казанский кремль",
      "short": "Кремль",
      "interests": ["history", "arch"],
      "price": "0–500 ₽",
      "priceNote": "вход на территорию бесплатно",
      "hours": "до 22:00",
      "blurb": "Белокаменная крепость ЮНЕСКО…",
      "highlights": ["Объект ЮНЕСКО", "Смотровые площадки"],
      "coords": [49.1056, 55.7985],
      "walkTo": 7,
      "walkBack": 7,
      "distance": "550 м",
      "eval": { "status": "fits", "visit": 60, "buffer": 46, "road": 14, "total": 74 }
    }
  ],
  "chain": {
    "total": 104,
    "buffer": 16,
    "walkBack": 14,
    "legs": [
      { "placeId": "museum", "walk": 3, "visit": 45 },
      { "placeId": "kremlin", "walk": 5, "visit": 50 }
    ]
  }
}
```

- `places` отсортированы: сначала `fits`, потом `tight`, потом `no`;
  внутри группы — по возрастанию `road`.
- `status` принимает `fits` (успеваешь), `tight` (впритык), `no` (не успеешь).
  Места со статусом `no` **остаются в ответе** — фронтенд показывает их
  серыми метками, это часть ценности продукта.
- `chain` — `null`, если пары, укладывающейся в бюджет, не нашлось.
- `legs[].placeId` ссылается на элемент `places`, чтобы не дублировать данные.

### Кто вызывает

`App.jsx → runSearch()`. Сейчас там синхронный вызов `pickPlaces`; станет:

```js
async function runSearch(minutes, interests, start) {
  const response = await fetch('/api/search', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: `tma ${initData}` },
    body: JSON.stringify({ start, minutes, interests }),
  });
  if (!response.ok) throw new Error('Подбор не удался');
  return response.json();
}
```

### При сбое

Показать экран «не получилось, попробуй ещё раз» с кнопкой повтора.
Это единственная ручка, без которой приложение бессмысленно.

### Как считать (перенести из `lib/planner.js` дословно)

```
walk(a, b)   = max(3, round(haversine_km(a, b) × 1.3 / 4.8 × 60))   // минуты
road         = walkTo + walkBack
BUFFER       = 10                                                   // мин про запас

fits   : minutes ≥ road + idealVisit + BUFFER  → visit = idealVisit
tight  : minutes ≥ road + minVisit   + BUFFER  → visit = minutes − road − BUFFER
no     : иначе                                 → visit = minVisit
```

Коэффициент `1.3` — поправка на то, что по улицам идёшь длиннее, чем по прямой.
Скорость `4.8 км/ч` — спокойный пешеходный шаг. Если подключите роутер
(см. `/api/route`), замените `walk()` на реальную длительность из него —
остальная формула не меняется.

Цепочка: перебрать пары мест со статусом не `no`, посчитать
`walkTo(a) + visitA + walk(a,b) + visitB + walkBack(b)`, отбросить те, что не
влезают в `minutes`, и выбрать пару с наибольшим `visitA + visitB`.
Время на местах округлять до 5 минут — план должен выглядеть как план,
а не как результат деления.

## 2. `POST /api/route` — геометрия пешего маршрута

Прокси к OpenRouteService. Нужна, чтобы ключ ORS не лежал в браузере
и чтобы кэшировать повторяющиеся маршруты.

### Запрос

```json
{ "points": [[49.1086, 55.7951], [49.1056, 55.7985]] }
```

От 2 до 10 точек. Порядок важен: первая — старт, последняя — финиш.
Для цепочки это `старт → место 1 → место 2 → старт`.

### Ответ

```json
{
  "line": [[49.1086, 55.7951], [49.1081, 55.7956], [49.1056, 55.7985]],
  "legs": [{ "duration": 6, "length": 527 }]
}
```

`line` — сплошная ломаная для слоя карты. `legs` — по одному участку на пару
соседних точек: `duration` в минутах, `length` в метрах.

### Кто вызывает

`lib/router.js → fetchRouteDetails()`, а её — `RouteScreen` и режим цепочки
в `ResultsScreen`.

```js
export async function fetchRouteDetails(points) {
  try {
    const response = await fetch('/api/route', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ points }),
    });
    if (!response.ok) return null;
    return await response.json();
  } catch {
    return null;   // молча падаем на прямую линию
  }
}
```

### При сбое

Вернуть `null`. Фронтенд нарисует прямую пунктирную линию между точками —
направление всё равно читается. **Тайминги от этой ручки не зависят**,
их считает `/api/search`, поэтому падение роутера не ломает продукт.

### Что делать на бэкенде

Дёрнуть ORS: `POST https://api.openrouteservice.org/v2/directions/foot-walking/geojson`
с заголовком `Authorization: <ключ>` и телом `{"coordinates": points}`.
Геометрия лежит в `features[0].geometry.coordinates`, участки —
в `features[0].properties.segments[]` (`duration` в секундах, `distance` в метрах).

**Кэшируйте.** Бесплатный тариф ORS — 2500 запросов в сутки на все сервисы.
Ключ кэша: округлённые до 4 знаков координаты всех точек. Переходы между
местами каталога вообще не меняются — их можно посчитать один раз при
деплое и положить в базу.

## 3. `GET /api/geocode` — поиск адреса

Прокси к геокодеру. Используется экраном ввода адреса.

### Запрос

```
GET /api/geocode?q=Кремлёвская 2&limit=6
```

| Параметр | Обязательный | Смысл |
|---|---|---|
| `q` | да | строка от 3 символов |
| `limit` | нет | сколько вернуть, по умолчанию 6 |

### Ответ

```json
{
  "results": [
    {
      "id": "address.123",
      "title": "улица Кремлёвская",
      "subtitle": "Казань, Республика Татарстан",
      "coords": [49.1063, 55.7963]
    }
  ]
}
```

Пустой `results` — валидный ответ, не ошибка.

### Кто вызывает

`lib/geocoder.js → searchAddress()`, экран `AddressScreen`.
Запрос уходит с задержкой 350 мс после последнего нажатия клавиши,
предыдущий отменяется через `AbortController` — иначе ответы приходят
вразнобой и список скачет под пальцем. Эту логику **оставьте во фронтенде**.

```js
const response = await fetch(`/api/geocode?q=${encodeURIComponent(text)}`, { signal });
```

### При сбое

Вернуть пустой список и показать «Ничего не нашлось». Экран карты остаётся
рабочим — метку всегда можно поставить рукой.

### Что делать на бэкенде

MapTiler: `GET https://api.maptiler.com/geocoding/{q}.json?key=…&language=ru&country=ru&proximity={lon},{lat}`.
`proximity` — центр города, иначе подсказки уезжают по всей стране.
Альтернатива — геокодер ORS (`/geocode/search`), он делит квоту с маршрутами.

## 4. `GET /api/interests` — список интересов

Справочник для экрана выбора. Сейчас лежит в `data/places.js`.

### Ответ

```json
{
  "interests": [
    { "id": "history", "label": "История", "icon": "museum" },
    { "id": "art",     "label": "Искусство", "icon": "palette" },
    { "id": "arch",    "label": "Архитектура", "icon": "building" },
    { "id": "walk",    "label": "Прогулка", "icon": "walk" },
    { "id": "food",    "label": "Еда", "icon": "food" },
    { "id": "photo",   "label": "Красивые места", "icon": "camera" },
    { "id": "culture", "label": "Культура", "icon": "masks" }
  ]
}
```

`icon` — ключ из набора в `components/Icon.jsx` (иконки Material Symbols,
вшиты в бандл). Бэкенд не присылает картинки, только имя иконки.
Если придумаете новый интерес — сначала добавьте иконку во фронтенд,
иначе она просто не отрисуется.

### При сбое

Использовать вшитый в бандл запасной список: экран выбора интересов не должен
падать из-за справочника.

## 5. `GET` / `POST /api/trips` — история поездок

Экран «Мои маршруты». Сейчас держится в памяти вкладки и теряется при
перезагрузке — это единственная ручка, ради которой нужна база.

### `GET /api/trips`

```json
{
  "trips": [
    {
      "id": "trip-kremlin-2026-09-22",
      "city": "Казань",
      "place": "Казанский кремль",
      "placeId": "kremlin",
      "date": "2026-09-22",
      "minutes": 85,
      "walkTo": 12,
      "visit": 60,
      "walkBack": 13,
      "interests": ["history", "arch"]
    }
  ]
}
```

Отсортировано от свежих к старым. Первая поездка показывается развёрнутой
карточкой с полосой времени, остальные — компактным списком.

`placeId` может быть `null` — так помечаются поездки из других городов,
которых нет в текущем каталоге. Фронтенд делает такие строки некликабельными:
повторить маршрут по ним нечем.

### `POST /api/trips`

Вызывается в момент построения маршрута — когда человек нажал
«Построить маршрут», а не когда реально дошёл.

```json
{
  "placeId": "kremlin",
  "minutes": 85,
  "walkTo": 12,
  "visit": 60,
  "walkBack": 13,
  "interests": ["history", "arch"],
  "start": [49.1086, 55.7951]
}
```

Ответ — созданная поездка в формате `GET`. Повторный вызов с тем же
`placeId` в тот же день должен вернуть существующую запись, а не плодить
дубликаты: человек мог открыть маршрут несколько раз.

### При сбое

`GET` — показать пустой экран истории с пояснением. `POST` — проглотить
ошибку молча: пользователь строит маршрут, а не сохраняет поездку,
ронять ему сценарий из-за этого нельзя.

## 6. `POST /api/session` — кто пользователь

Нужна, как только появится история: иначе непонятно, чьи поездки отдавать.

### Запрос

```json
{ "initData": "query_id=…&user=…&auth_date=…&hash=…" }
```

Строка, которую MAX кладёт в mini-app при открытии.

### Ответ

```json
{ "userId": "max:123456789", "displayName": "Тимофей", "city": "Казань" }
```

`city` определяет, какой каталог мест отдавать — сейчас он один, но
закладываться стоит сразу.

### Что делать на бэкенде

**Проверить подпись `initData`.** Без проверки любой сможет притвориться
кем угодно и читать чужую историю. Алгоритм — в документации MAX для
мини-приложений; он такой же, как в Telegram Web Apps: HMAC от отсортированных
полей на ключе, производном от токена бота.

Дальше выдавайте свою сессию (кука `HttpOnly` или JWT) и не гоняйте
`initData` в каждом запросе.

## Порядок переезда

Ручки независимы — их можно включать по одной, фронтенд переживает отсутствие
любой. Разумный порядок:

1. **`/api/route` и `/api/geocode`** — чистые прокси, логики нет. Сразу
   убирают ключи из браузера. Час работы, заметная польза.
2. **`/api/search`** — перенос `planner.js`. Файл написан без зависимостей
   от React и браузера, на Node переносится почти как есть. После этого бот
   и mini-app считают по одной формуле.
3. **`/api/interests`** — мелочь, делается заодно с предыдущим пунктом.
4. **`/api/session` и `/api/trips`** — последними: только ради них нужна база.

## Что остаётся во фронтенде

Не переносите на бэкенд:

- **Задержку и отмену запросов геокодера** — это про отзывчивость ввода,
  сервер тут ни при чём.
- **Состояние сценария** (выбранное время, интересы, точка старта, текущий
  экран) — оно живёт до нажатия «Показать варианты» и серверу не интересно.
- **Отрисовку карты и маршрута** — MapLibre рисует в браузере, бэкенд отдаёт
  только координаты.

## Чего в контракте намеренно нет

- **Пагинации** у `/api/search`: каталог мест конечный и маленький, отдавать
  его целиком дешевле, чем городить курсоры.
- **Отдельной ручки `/api/places`**: каталог без посчитанных таймингов
  фронтенду не нужен ни на одном экране.
- **WebSocket**: ничего не меняется в реальном времени. Если появится
  «место закрылось прямо сейчас» — это повод пересмотреть, а пока лишняя
  сложность.

## Переменные окружения бэкенда

```bash
ORS_API_KEY=            # OpenRouteService, маршруты; бесплатно, 2500/сутки
MAPTILER_KEY=           # геокодер (и тайлы для фронтенда)
MAX_BOT_TOKEN=          # для проверки подписи initData
DATABASE_URL=           # нужен только для /api/trips
```

Ключи, которые сейчас лежат во фронтенде (`VITE_ORS_API_KEY`,
`VITE_MAPTILER_KEY`), после переезда остаются только на сервере.
Исключение — `VITE_MAPTILER_KEY`: тайлы карты браузер грузит напрямую,
поэтому этот ключ остаётся в бандле и защищается ограничением по HTTP Referer
в кабинете MapTiler.
