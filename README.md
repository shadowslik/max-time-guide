# max-time-guide («Успеть»)

Мини-приложение и чат-бот в мессенджере **MAX** для трека «Досуг и развлечения».

> ⚠️ **Статус данных:** в MVP используется собственный **подготовленный (тестовый) датасет** мест по одному городу. Реальная интеграция с внешними системами не выполняется — см. раздел «Работа с данными».

---

## 1. Назначение решения

Турист приезжает в незнакомый город с ограниченным временем (командировка, пересадка, поездка на выходные) и привязкой к точке старта (вокзал / отель). Информация о том, что посмотреть, раскидана по картам, блогам и афишам, и свести её вручную под своё время — долго и рискованно (место закрыто, слишком далеко, не успел вернуться).

**max-time-guide** по введённым параметрам (город, точка старта, доступное время, интересы) за пару минут строит **готовый упорядоченный маршрут** из топ-мест, которые реально влезают в отведённое время, с учётом часов работы и запаса на возврат.

## 2. Основной пользовательский сценарий

1. Пользователь открывает бота в MAX и нажимает «Собрать маршрут» → открывается мини-приложение.
2. Вводит: **город** (в MVP — Казань), **точку старта**, **сколько есть времени** (3 ч / 6 ч / 1 день / 2 дня), **интересы**, при желании фильтр «только бесплатные места».
3. Получает **маршрут**: упорядоченный список мест с таймингом, временем перехода между ними, часами работы и статусом «успеваешь вернуться к HH:MM».
4. Может пересобрать маршрут или убрать место.

## 3. Состав и архитектура решения

| Компонент | Технологии | Роль |
|---|---|---|
| Чат-бот | Python (aiomax / httpx) | Точка входа в MAX, запуск мини-приложения |
| Backend API | Python, FastAPI | Эндпоинт генерации маршрута, алгоритм подбора |
| Мини-приложение | React + Vite + MAX UI + MAX Bridge | Ввод параметров и отображение маршрута |
| Данные | JSON-датасет | Подготовленные места по городу |

Схема: `Пользователь → MAX → чат-бот → мини-приложение → Backend API (/route) → датасет`.

Алгоритм подбора: жадный выбор мест по отношению «приоритет / (время в пути + время осмотра)» с учётом окна времени, часов работы и буфера на возврат. Время в пути — **модельная оценка** (расстояние / средняя скорость), помечена как приблизительная.

## 4. Запуск всех локальных компонентов одной командой (Docker)

```bash
docker compose up --build
```

## 5. Необходимые параметры окружения

Перед запуском создайте файл `.env` на основе `.env.example` и укажите токен бота MAX, выданный организаторами.

## 6. Переменные окружения

| Переменная | Назначение | Пример |
|---|---|---|
| `MAX_BOT_TOKEN` | Токен чат-бота MAX (**секрет, не коммитить**) | `xxxxx...` |
| `MAX_API_BASE_URL` | Базовый адрес Bot API MAX | `https://platform-api2.max.ru` |
| `REQUESTS_CA_BUNDLE` | Путь к CA-бандлу с сертификатами Минцифры | `/app/certs/ca-bundle.pem` |
| `API_PORT` | Порт backend API | `8000` |
| `DATA_FILE` | Путь к файлу датасета | `app/data/kazan.json` |

## 7. Используемые порты

| Порт | Компонент |
|---|---|
| `8000` | Backend API (FastAPI) |
| `8080` | Мини-приложение (статика, в Docker) |
| `5173` | Мини-приложение (Vite dev-сервер, локально) |

## 8. Зависимости

- Backend: см. `backend/requirements.txt` (FastAPI, uvicorn, httpx/aiomax, pydantic).
- Frontend: см. `frontend/package.json` и `frontend/package-lock.json` (React, Vite, MAX UI, MAX Bridge).

## 9. Внешние сервисы и интеграции

- **MAX Bot API** (`platform-api2.max.ru`) — доставка сообщений и запуск мини-приложения. Требует сертификаты НУЦ Минцифры (лежат в `certs/`).
- Мини-приложение MAX требует доступа по **HTTPS**.

## 10. Работа с данными

Данные о местах (название, координаты, время осмотра, часы работы, категория, признак бесплатности) хранятся в подготовленном датасете `backend/app/data/kazan.json`.

Датасет наполнен из официальных источников (Путешествуем.рф, сайты учреждений, ФИАС для адресов) и является **curated/тестовым**: реальная онлайн-интеграция с внешними системами в MVP не выполняется. Каждая запись содержит поле `data_actual_on` (дата актуальности) и `source` (источник).

## 11. Порядок работы с тестовыми данными

Тестовый датасет уже включён в репозиторий и загружается автоматически при старте backend. Отдельная настройка не требуется. Формат одной записи описан в `backend/app/models/schemas.py`.

## 12. Пошаговый сценарий проверки

1. Заполнить `.env` (токен бота из презентации, служебный слайд).
2. Выполнить `docker compose up --build`.
3. Дождаться старта backend (лог `Uvicorn running on ...`) и бота.
4. Открыть чат-бота в MAX по никнейму (указан на служебном слайде), нажать «Начать» → «Собрать маршрут».
5. Ввести: Казань, точка старта «Ж/д вокзал», время «6 часов», интересы «история, еда».
6. Убедиться, что вернулся упорядоченный маршрут с таймингом и статусом возврата.

## 13. Примеры ожидаемого поведения

- **Достаточно времени:** маршрут из 4–6 мест, итоговое время ≤ заданного окна, статус «успеваешь вернуться к 17:40».
- **Мало времени (3 ч):** маршрут из 2–3 ближайших мест, дальние отсекаются.
- **Фильтр «только бесплатные»:** в маршруте только места с `is_free = true`.
- **Место закрыто в это время:** исключается из маршрута.

## 14. Известные ограничения

- Один город (Казань), горизонт до 1–2 дней, без ночёвки.
- Время в пути — приблизительная модельная оценка, не реальная маршрутизация.
- Датасет тестовый; часы работы и цены могут отличаться от актуальных.
- Подбор жилья, несколько городов и многодневные поездки в MVP не входят.

## 15. Порядок остановки и повторного запуска

Остановить:

```bash
docker compose down
```

Запустить снова:

```bash
docker compose up
```
