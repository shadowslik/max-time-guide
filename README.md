# max-time-guide

Чат-бот и мини-приложение в мессенджере **MAX** (трек «Досуг и развлечения»).

> Данные MVP — подготовленный тестовый датасет по одному городу (Казань). Реальной интеграции с внешними системами нет.

## Назначение

Помогает туристу с ограниченным временем в незнакомом городе получить готовый маршрут: по городу, точке старта, доступному времени и интересам строит упорядоченный список топ-мест, которые успеваешь посмотреть с учётом часов работы и запаса на возврат.

## Основной сценарий

1. Открыть бота в MAX → «Собрать маршрут» → откроется мини-приложение.
2. Ввести город, точку старта, доступное время, интересы.
3. Получить маршрут: места по порядку, тайминг, переходы, статус «успеваешь вернуться».

## Архитектура

| Компонент | Стек | Роль |
|---|---|---|
| Бот | Python, aiomax | Вход в MAX, кнопка запуска мини-аппа |
| Backend API | Python, FastAPI | Эндпоинт `/route`, алгоритм подбора |
| Мини-приложение | React + Vite | UI: ввод параметров и маршрут |
| Данные | JSON-датасет | Тестовые места по городу |

Поток: `MAX → бот → мини-приложение → API /route → датасет`.

## Запуск (Docker, одна команда)

```bash
docker compose up --build
```

Поднимает `bot` и `frontend` (локальная копия). Перед запуском создать `.env` из `.env.example`.

## Переменные окружения

| Переменная | Назначение | Обяз. |
|---|---|---|
| `MAX_BOT_TOKEN` | Токен бота MAX (секрет, не коммитить) | да |
| `BOT_USERNAME` | Ник бота, к которому привязан мини-апп | да |
| `MAX_API_BASE_URL` | Адрес Bot API (по умолчанию `https://platform-api2.max.ru`) | нет |

## Порты

| Порт | Компонент |
|---|---|
| `8080` | Мини-приложение (nginx в Docker) |
| `5173` | Мини-приложение (Vite dev, локально) |
| `8000` | Backend API (FastAPI) |

## Зависимости

- Backend: `backend/requirements.txt` (aiomax, FastAPI, uvicorn, httpx, pydantic).
- Frontend: `frontend/package.json` + `package-lock.json` (React, Vite).

## Внешние сервисы

- **MAX Bot API** (`platform-api2.max.ru`) — доставка сообщений, запуск мини-аппа. Сертификаты НУЦ Минцифры подключаются автоматически (`aiomax`, `use_certificate=True`).
- **Мини-приложение** размещено на публичном HTTPS (Cloudflare): `https://max-time-guide.ovoaookaaooaoa.workers.dev` — MAX открывает эту версию; Docker-копия нужна для локальной проверки.

## Работа с данными

Места (название, координаты, время осмотра, часы работы, категория, признак бесплатности) хранятся в JSON-датасете в `backend/`. Датасет **тестовый/curated**, наполнен из официальных источников (Путешествуем.рф, сайты учреждений, ФИАС); каждая запись помечена источником и датой актуальности. Онлайн-интеграции нет.

## Тестовые данные

Датасет включён в репозиторий и загружается при старте backend — отдельная настройка не нужна.

## Проверка

1. Создать `.env` (токен и ник бота — на служебном слайде презентации).
2. `docker compose up --build`.
3. Открыть бота в MAX по нику, нажать «Начать» → «Собрать маршрут».
4. Ввести: Казань, точка старта, время → получить упорядоченный маршрут.

## Примеры поведения

- Времени хватает → маршрут из 4–6 мест, влезает в окно, статус «успеваешь вернуться».
- Мало времени → 2–3 ближайших места, дальние отсекаются.
- Фильтр «бесплатные» → только места с `is_free = true`.
- Место закрыто → исключается.

## Ограничения

- Один город, горизонт до 1–2 дней, без ночёвки.
- Время в пути — модельная оценка, не реальная маршрутизация.
- Датасет тестовый; часы работы и цены могут отличаться.
- Жильё, несколько городов и многодневные поездки не входят в MVP.
