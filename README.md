# max-time-guide

Чат-бот и мини-приложение в мессенджере **MAX** (трек «Досуг и развлечения»).

> Места берутся вживую из **2ГИС Catalog API** (по всей РФ), адрес и часовой пояс — из **DaData**, тайлы карты — из **OpenFreeMap**. Если ключа 2ГИС нет — работает фолбэк на OpenStreetMap Overpass. Небольшой curated-датасет по Казани используется только как офлайн-фолбэк и для демо-истории — это явно помечено ниже.

## Назначение

Помогает туристу с ограниченным временем в незнакомом городе получить готовый маршрут: по городу, точке старта, доступному времени и интересам строит упорядоченный список топ-мест, которые успеваешь посмотреть с учётом часов работы и запаса на возврат.

## Основной сценарий

1. Открыть бота в MAX → «Собрать маршрут» → откроется мини-приложение.
2. Ввести город, точку старта, доступное время, интересы.
3. Получить маршрут: места по порядку, тайминг, переходы, статус «успеваешь вернуться».

## Архитектура

| Компонент | Стек | Роль |
|---|---|---|
| Бот | Python, aiomax | Вход в MAX, кнопка запуска мини-аппа |
| Backend API | Python, FastAPI | Подбор мест и цепочек: `/api/search`, `/api/route`, `/api/geocode`, `/api/reverse`, `/api/interests`, `/api/trips`, `/api/profile` |
| Мини-приложение | React + Vite + MapLibre GL | UI: ввод параметров, карта, маршрут, профиль |
| Хранилище | SQLite | Профиль и история просмотренных маршрутов |
| Прокси | Caddy | HTTPS наружу, `/api/*` → backend, остальное → статика |
| Данные о местах | 2ГИС Catalog API (+ DaData, OpenFreeMap) | Реальные места по РФ; OSM Overpass — фолбэк |

Поток: `MAX → бот → мини-приложение → Caddy → API /api/search → 2ГИС/DaData → цепочка мест`.

## Запуск (Docker, одна команда)

```bash
docker compose up --build
```

Поднимает весь стек (`caddy` + `frontend` + `backend`), как на сервере. Перед запуском создать `.env` из `.env.example`.

- **Локально** открывать **http://localhost** (Caddy отвечает и на `localhost`, и на серверный домен — см. [Caddyfile](Caddyfile)). `/api` проксируется на бэкенд тем же Caddy, порты контейнеров наружу пробрасывать не нужно.
- Бот берёт `MAX_BOT_TOKEN` из `.env` (тот же, что на сервере) — **останови серверного бота перед локальным запуском**, иначе оба тянут одни апдейты MAX. Не нужен бот локально — поставь `RUN_BOT=0` в `.env`.

## Переменные окружения

| Переменная | Назначение | Обяз. |
|---|---|---|
| `MAX_BOT_TOKEN` | Токен бота MAX (секрет, не коммитить) | да |
| `BOT_USERNAME` | Ник бота, к которому привязан мини-апп | да |
| `MAX_API_BASE_URL` | Адрес Bot API (по умолчанию `https://platform-api2.max.ru`) | нет |
| `RUN_BOT` | Поднимать ли бота вместе с API (`0` — только API, удобно локально) | нет |
| `API_PORT` | Порт API (по умолчанию `8000`) | нет |

## Внешние сервисы

| Сервис | Назначение | Ключ | Роль |
|---|---|---|---|
| **MAX Bot API** (`platform-api2.max.ru`) | доставка сообщений, запуск мини-аппа | `MAX_BOT_TOKEN` | обязательно |
| **2ГИС Catalog API** (`catalog.api.2gis.com`) | места по РФ: категории, рейтинг, отзывы, часы работы | `TWOGIS_KEY` | основной источник мест |
| **DaData** (`dadata.ru`) | геокодинг адреса и регион/часовой пояс по координатам | `DADATA_TOKEN` | геокодинг, «открыто сейчас» |
| **KudaGo / PRO.Культура.РФ** | культурные события, «Пушкинская карта» | `CULTURE_API_KEY` (PRO) | события (опц.) |
| **OpenRouteService** (`api.openrouteservice.org`) | геометрия пешего маршрута | `VITE_ORS_API_KEY` | опц., иначе прямая линия |
| **OpenFreeMap** (`tiles.openfreemap.org`) | векторные тайлы карты | — | тайлы (без ключа) |
| **OSM Overpass / Nominatim** | места и геокодинг | — | фолбэк, если нет `TWOGIS_KEY`/`DADATA_TOKEN` |

Мини-приложение и API отдаёт Caddy по HTTPS с того же VPS; отдельного хостинга фронта нет.

## Работа с данными

Разделение по происхождению (как требует трек):

- **Реальные данные (внешние API).** Места, рейтинг, отзывы и часы работы — вживую из 2ГИС по точке старта и интересам. Адрес и часовой пояс региона — из DaData. События — из KudaGo/Культура.РФ. Тайлы — OpenFreeMap.
- **Расчёт продукта.** Время пешком (haversine × коэффициент извилистости), тайминг цепочки, гарантия возврата с запасом, статусы «успеваешь / впритык / не успеешь», отбор по рейтингу ≥ 4.5 и наличию отзывов, фильтр «открыто сейчас» по местному времени.
- **Curated/фолбэк (в репозитории).** Небольшой набор мест по Казани (`backend/app/data/places.py`) и демо-история — используются как офлайн-фолбэк и для наполнения профиля. Это **тестовые, заранее подготовленные данные**, не выдаются за онлайн-источник.

Профиль и история просмотренных маршрутов хранятся в SQLite (`backend/data/app.db`, в Docker — на именованном томе, переживает пересборку).

## Тестовые данные

- Curated-набор по Казани и демо-история включены в репозиторий и загружаются при старте — отдельная настройка не нужна.
- Для боевого качества подбора нужен `TWOGIS_KEY` (и желательно `DADATA_TOKEN`) в `.env`. Без 2ГИС бэкенд отдаёт места из OSM Overpass — менее полно и стабильно; это ожидаемое поведение фолбэка.

## Проверка

1. Создать `.env` из `.env.example` (токен/ник бота и ключи `TWOGIS_KEY`, `DADATA_TOKEN` — на служебном слайде презентации).
2. `docker compose up --build` → открыть **http://localhost** (локально) или задеплоенный HTTPS-адрес.
3. Быстрая техпроверка API без MAX:
   - `curl http://localhost/api/health` → `{"status":"ok"}`;
   - `curl -X POST http://localhost/api/search -H 'Content-Type: application/json' -d '{"start":[49.1086,55.7951],"minutes":180,"interests":["history","walk"]}'` → список мест + цепочка.
4. Полный сценарий: открыть бота в MAX → «Начать» → «Собрать маршрут» → указать точку старта, время и интересы → получить упорядоченный маршрут с таймингом.

## Примеры поведения

- Времени хватает → цепочка из нескольких мест, влезает в окно, статус «успеваешь вернуться»; в шапке — сколько мест реально успеть.
- Мало времени на все интересы → предлагаются варианты цепочки по подмножествам интересов.
- Много достижимых мест, но за окно все не обойти → показывается максимум мест, влезающих в бюджет (напр. «Успеешь 5 из 11»).
- Место закрыто в момент старта (по местному времени) → исключается из подбора.
- Битый запрос (координаты вне диапазона, нет обязательных полей) → `400` со структурой `{"error":{"code","message"}}`.
- Открытие маршрута из истории профиля → строится простой маршрут «точка старта → место», без пересборки подбора.

## Ограничения

- Качество подбора зависит от 2ГИС: без `TWOGIS_KEY` работает фолбэк на OSM Overpass (менее полно/стабильно).
- Время в пути — модельная оценка (haversine × коэффициент); реальная геометрия только при наличии `VITE_ORS_API_KEY`.
- Часы работы и рейтинги берутся из 2ГИС и могут отставать от факта.
- События (Культура.РФ) подмешиваются только при наличии PRO-ключа; без него — только места.
- Один прогулочный сценарий в пределах города: без жилья, транспорта между городами и многодневных поездок.
